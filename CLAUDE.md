## Project Overview

**pi-manager** is a full-stack app for monitoring Raspberry Pi resources. The backend is a Go API server that syncs a managed directory into SQLite and exposes HTTP endpoints. The frontend is a React + TypeScript + Vite app that visualizes disk and file data.

## Commands

### Backend (Go)

```bash
cd backend
go build ./...                          # Build all packages
go build -o api ./cmd/api               # Build the server binary
go run ./cmd/api                        # Run server (requires env vars)
go test ./...                           # Run all tests
go test ./internal/store/...            # Run a specific package's tests
```

Required env vars when running locally:
```
MANAGED_DIR=/path/to/monitor    # Required
PORT=8080                        # Optional, default 8080
DB_PATH=./pi-manager.db          # Optional
```

#### sqlc (code generation)

SQL queries are in `backend/internal/store/query.sql`. After editing them, regenerate Go code:
```bash
cd backend && sqlc generate
```
Do not manually edit `query.sql.go` — it is generated by sqlc.

### Frontend (React)

```bash
cd frontend
npm install
npm run dev        # Dev server with HMR
npm run build      # TypeScript check + Vite bundle
npm run lint       # ESLint
npm run test       # Vitest
```

### Docker (full stack)

```bash
docker-compose up --build    # Build and run backend + frontend
```

Targets `linux/arm64` (Raspberry Pi). Backend serves on port 8080, frontend on port 80 via Nginx.

## Architecture

### Backend

```
backend/
├── cmd/api/main.go          # Entry point: env vars → DB init → sync → HTTP server
└── internal/
    ├── disk/                # syscall.Statfs wrapper → DiskStats
    ├── handler/             # HTTP handlers (DiskHandler, FilesHandler)
    ├── scanner/             # Filesystem walk + DB sync (runs at startup + every minute)
    └── store/               # SQLite layer via sqlc-generated code
        ├── schema.sql       # Single `files` table definition
        ├── query.sql        # sqlc source queries
        └── query.sql.go     # Generated — do not edit
```

**Data flow**: `scanner.Sync` walks `MANAGED_DIR` recursively → calls `store.UpsertFile` per entry → calls `store.DeleteMissing` to prune stale records. Runs at startup and every 60s.

**Database schema** — `files` table:
- Hierarchical: `parent_id INTEGER REFERENCES files(id) ON DELETE CASCADE`
- `path TEXT NOT NULL UNIQUE` — absolute path
- Timestamps: `modified_at` (from filesystem), `synced_at` (last scan), both Unix seconds

### Frontend

```
frontend/src/
├── app/router.tsx           # TanStack Router: root layout → dashboard route
├── features/disk-usage/     # Feature module pattern: types, api, query hook, UI component
├── pages/dashboard/         # Dashboard page — composes feature components
├── layouts/LayoutMain.tsx   # Shared layout wrapper
└── shared/api/client.ts     # Base fetch client (base URL: /api)
```

**Frontend conventions**:
- Always use named exports — never `export default`

**Frontend patterns**:

This is a dashboard-style app. The key rules:

- **Components** are the base building blocks. Each component fetches its own data (via React Query) and handles its own loading/error states independently — a failing widget must not block the rest of the page. Components are designed to be reusable across pages.
- **Layouts** arrange components using HTML structure. They may contain base HTML elements but no business logic unless explicitly specified.
- **Pages** are composed exclusively of layouts and components — no raw HTML elements. Pages are oblivious to what data their components load; they only decide which components and layouts to render.
- API calls live in `features/<name>/api/`, React Query hooks in `features/<name>/queries/`.

### API Endpoints

| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/disk` | Disk usage stats (`total_bytes`, `used_bytes`, `free_bytes`, `used_percent`) |
| GET | `/api/files` | List children (`?parent_id=<id>`, omit for root) or search the whole tree (`?q=&extension=&min_size=&limit=`) |
| DELETE | `/api/files/{id}` | Delete a file or directory (cascades) |
| GET | `/api/directories/{id\|root}/usage` | Direct children with recursive total sizes (treemap data) |
| GET | `/api/file-types` | Space by content category with top extensions |
| GET | `/api/changes` | Recent sync-detected changes (`?limit=`, default 50) |
| GET/POST | `/api/downloads` | List / start background downloads |
